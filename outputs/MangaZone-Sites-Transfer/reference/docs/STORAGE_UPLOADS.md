# Storage/upload foundation and COVER finalize (4.3A / 4.3B)

PAGE now extends the shared finalize/storage infrastructure in 4.4C with its own
limits and private authorization. See [EDITORIAL_PAGES.md](EDITORIAL_PAGES.md).
The historical COVER-specific scope and policy below remain unchanged.

## Scope and environment

The bucket is PRIVATE. Provision it outside the application: disable anonymous read/write,
public ACLs and bucket listing. Use a least-privilege server credential: PutObject for
`tmp/editorial/*` and `media/manga-covers/*`; GetObject for temporary inspection and trusted
final delivery; DeleteObject only for those two namespaces. The application neither creates
a bucket nor changes its ACL/policy. Configure TLS in production and storage quotas externally.

Server-only configuration reuses `OBJECT_STORAGE_ENDPOINT`, `OBJECT_STORAGE_REGION`,
`OBJECT_STORAGE_BUCKET`, `OBJECT_STORAGE_ACCESS_KEY`, `OBJECT_STORAGE_SECRET_KEY`.
All five absent/blank disables signing (safe 503); partial configuration fails startup.
`OBJECT_STORAGE_FORCE_PATH_STYLE` accepts `true` (default) or `false` for provider compatibility.
`MEDIA_API_ORIGIN` is the public HTTP(S) origin of the API/reverse proxy, NOT the bucket;
it is required when storage is configured. Both origins forbid embedded credentials,
paths/query/hash and require HTTPS in production. No secret is a Web/public env variable.

Example for an independently provisioned local MinIO: endpoint `http://localhost:9000`,
region `us-east-1`, private bucket `mangazone`, path style `true`, media API origin
`http://localhost:3001`. Supply credentials privately. No MinIO service is installed by 4.3A.
Bucket CORS must allow the exact Web origin and PUT with Content-Type; HTTP clients must
send the exact signed Content-Length. Browsers compute Content-Length from the File/Blob;
do not manually set that forbidden browser header or upload multipart/form-data.
Protected cover requests require the existing session cookie to reach the API;
production should route `/media` through the session-compatible API/reverse proxy origin.
Set Web's existing `NEXT_PUBLIC_API_URL` to the same public origin as `MEDIA_API_ORIGIN`.
The Manga cover component recognizes only that configured origin plus the exact UUID cover
route, then uses Next Image `unoptimized`: the browser requests the API directly with its
normal cookie rules. There is no Next image proxy/cache or remote-pattern allowlist for it.
Local/demo images keep their existing behavior. Origin inputs are validated and canonicalized
with URL.origin; ambiguous forms such as `https:host`, paths, query and fragments are rejected.

## Upload contract

`POST /editorial/uploads/intents` returns 201. Guards: Session, Origin, CSRF, Permission.
Actor comes only from CurrentAuth. ACTIVE global ADMIN or `catalog.manage` is required,
including a live authorization recheck in the persistence transaction. Group roles and
moderation permissions confer no authority. Unknown body properties are rejected.

Body: `purpose: "MANGA_COVER"` (the existing Prisma name for COVER), `mangaId` UUID,
`contentType` exactly image/jpeg, image/png or image/webp, `expectedBytes` integer
1..10,485,760. `maxBytes` is always 10,485,760 server-side, exclusively for MANGA_COVER.
No PAGE/BANNER contract is added. Manga must exist; no cover association occurs.

Response fields: intentId, method PUT, signedUploadUrl, headers, expiresAt ISO string.
Intent UUIDv7 is generated by Prisma. The temporary key uses a separate cryptographic
random UUID under `tmp/editorial/`, not an actor, filename or user-controlled path.
No Asset row is created. MIME is bound into the signature, not added as a schema field.
The existing intent stores the expected bytes, limit, actor, manga, key, state and expiry.

Intent and PUT signature share a server timestamp and a five-minute expiry.
The SDK signs the exact key, bucket, Content-Type and Content-Length. Signing uses explicit
local credentials outside the DB transaction (no remote credential discovery). No URL is
returned unless persistence succeeds. Unexpected signer failures produce a sanitized 503.
No presigned URL is stored or explicitly logged.

SigV4 necessarily embeds the opaque object path, credential identifier and signature in
the signed URL. There is no separate raw key/credential field, and no secret key is exposed.
Treat signed URLs as bearer capabilities; redact query strings and Location/response bodies
in proxy/APM/storage access logs. They can be replayed until expiry, are not single-use PUTs,
and are not instantly revoked by an account/permission change.

## COVER finalize (4.3B)

Declared MIME/size and signed headers DO NOT validate actual image content. A temporary
object is not READY and cannot be delivered by the cover endpoint, even if incorrectly
referenced as an Asset. `isPendingUploadIntent` requires PENDING and expiresAt strictly after now;
expired, FINALIZED and REJECTED intents are unusable. No automatic expiry-state update is needed.
The DB already constrains positive bytes, max >= expected, valid context and finalization fields.
No schema/migration change is needed: existing FINALIZED/finalizedAt/unique assetId and checks suffice.

`POST /editorial/uploads/intents/:intentId/finalize` accepts an empty JSON object and returns
200 with `{ intentId, assetId, mangaId, finalizedAt }`, no storage key or signed URL.
It reuses Session -> Origin -> CSRF -> Permission and requires the SAME actor who created
the intent, still ACTIVE ADMIN/catalog.manage. Other actors receive neutral 404 even if ADMIN.
No body override for manga, actor, bytes, MIME or final key is allowed.

Inspection uses one bounded GET, not HEAD followed by a second potentially different GET.
Content-Length and Content-Type belong to that response snapshot. The stream is stopped and
destroyed above 10,485,760 bytes; the actual positive length must match BOTH response
Content-Length and persisted expectedBytes exactly. Missing/contradictory length is rejected.
The object Content-Type was bound by 4.3A's signed PUT; no new client MIME is accepted at finalize.
It must match the decoded format. This still requires the provider to enforce signed headers
and bucket policy to forbid unrelated writers; metadata alone is never accepted as image proof.

V1 COVER accepts STATIC, single-frame JPEG/PNG/WebP only. Bounded container walks reject
PNG acTL/fcTL/fdAT and WebP VP8X animation flags/ANIM/ANMF independently of Sharp metadata;
malformed/truncated chunk lengths and trailing container data fail closed. Other containers,
including SVG/GIF/AVIF/TIFF/BMP, are rejected before decode. Metadata also rejects multiple pages.
These checks are not decoders or CRC-based substitutes for pixel validation.

Sharp 0.34.5 (direct API dependency) fully decodes static pixels using an OUTPUT pipeline:
failOn=warning, limitInputPixels=16,777,216, sRGB + alpha, raw uchar, timeout(10 seconds),
toBuffer. Unlike stats(), this path installs Sharp's native processing timeout. The deadline
is native processing time, not a wall-clock deadline covering metadata, queueing or storage.
No Promise.race is used: the slot remains held until native output completes or aborts.
The raw buffer is discarded after validation; only original bytes are hashed and promoted.
Corruption/truncation, fake headers and excess input pixels are rejected.

Explicit raw-output bound: 16,777,216 pixels * 4 channels * 1 byte = 67,108,864 bytes
(64 MiB), or 128 MiB for two simultaneous outputs. Conversion to sRGB and uchar also bounds
16-bit PNG and CMYK JPEG output; dimensions/channels/size are checked after decode.
At most two finalizers are in flight per API process (503 UPLOAD_FINALIZE_BUSY otherwise),
including storage and decode. Raw references are not retained, but reclamation is GC-managed.
The 128 MiB figure is NOT total RSS: allow compressed buffers, native intermediate images,
libvips caches, GC lag and normal API/DB work as additional overhead. There is no deployment
memory limit configured in this repository; provision and load-test the actual runtime with
headroom above this output budget. Do not assume a 128 MiB container is sufficient.
Pixel/concurrency limits are unchanged; these are safety limits, not cover-layout requirements.

SHA-256 is lowercase hex over the original validated bytes. The same bounded buffer is PUT
create-only (If-None-Match: *) to `media/manga-covers/<cryptographic-random-uuid>` with actual MIME,
length and private/no-store. No copy of the mutable temporary key is performed. Thus replaying
the original signed PUT cannot change promoted bytes. The final object key contains no PII.
Asset UUIDv7 is generated by Prisma independently of the opaque storage key.
An explicit PreconditionFailed/HTTP 412 from final PUT becomes an internal object-exists
error and sanitized HTTP 409 UPLOAD_FINAL_KEY_CONFLICT. It is not an outage: no overwrite,
key regeneration/retry, DB mutation or DELETE is attempted. Other PUT errors remain 503.

Only after final PUT succeeds, a short default-isolation DB transaction locks the intent row
(SELECT FOR UPDATE), rechecks DB-fresh authority/context/state/expiry, creates READY with
real MIME/size/dimensions/hash, conditionally sets PENDING -> FINALIZED + finalizedAt/assetId,
and associates Manga.coverAssetId. Manga.version increments to invalidate stale editor writes.
No storage/network/decode work occurs while holding the row lock. Concurrent finalizers can
stage distinct final objects, but only one consumes the locked intent; the loser rolls back
all DB writes and cleans its own unreferenced final object. Repeat finalize is a controlled 409,
not a second Asset. Existing cover Asset/object is retained, never destructively deleted.

### Failure matrix and cleanup

| Failure | DB result | Storage result |
| --- | --- | --- |
| Invalid/expired intent, missing/invalid bytes | No Asset/association/finalization | No promotion; temporary may remain |
| Final PUT create-only conflict (412) | No productive DB writes | Existing object is never overwritten/deleted; 409, no retry |
| Final PUT fails | No productive DB writes | Outcome may be ambiguous; log sanitized reconciliation event, retain uncertain object |
| DB transaction fails after PUT | No partial commit | Re-lock intent in a fresh transaction before checking final-key reference; best-effort delete only if unreferenced |
| Commit/reconciliation outcome unknown | Never presume rollback | Retain final object rather than risk deleting referenced bytes; sanitized warning |
| Temporary DELETE fails after DB success | Finalize remains successful | Sanitized warning; temporary left for operational cleanup |

PostgreSQL and S3 are NOT atomic together. Cleanup is best-effort, and final orphan objects
remain possible during outages. SDK operations have 30-second abort deadlines. Log events do
not include keys, bucket, provider messages, signed URLs or credentials. Unknown DB errors
use the platform's existing sanitized HTTP 500 handling; known intent conflicts use 409,
object missing 404, invalid size/MIME/image 400 and storage unavailable 503.

After commit, temporary deletion is attempted. A presigned PUT remains replayable until its
original expiry and can recreate the temporary object after deletion, but cannot finalize
again or touch the separate final key. Configure temporary retention/GC operationally;
URL expiry alone does not delete objects. No scheduled cleanup/GC, Web upload UI, PAGE/BANNER,
resize, transcoding, optimization or malware scanning is added by this phase.

## Controlled COVER delivery

`GET /media/mangas/:id/cover`: optional session, READY associated cover only. PUBLIC and
non-ADULT Manga follows the existing public catalog policy. Private DRAFT/HIDDEN covers require
live ACTIVE ADMIN/catalog.manage or DB-fresh editorial project-read scope for a project of that
same Manga; ADULT remains ADMIN/catalog.manage-only. This read does not grant cover upload or
Manga mutation. Uploader/asset ownership alone is not authority. No generic asset/key endpoint
exists. Missing/anonymous private cases are neutral 404; authenticated unauthorized readers
receive the existing permission error. Non-READY, temporary/unsafe keys and non-jpeg/png/webp
objects are not signed.

Authorized requests redirect (302) to a 60-second exact-key signed GET. The redirect and object
override use private/no-store, with no-referrer on the redirect. A URL already issued remains
a bearer capability until expiry; this bounded window also applies to subsequent visibility changes.

Cover mappers for catalog/detail, editorial, library/lists and history now emit this controlled
route, not bucket/key URLs. Existing safe `/demo/*` fixtures remain public static fixtures and
are NOT private storage; they must never contain confidential media. Without MEDIA_API_ORIGIN,
real-key cover URLs are omitted rather than falling back to raw keys. The 4.3A Web wrapper
adapts controlled covers to direct browser requests; 4.3B adds no Web changes.
Reader PAGE and other domain media resolvers are legacy and unchanged: 4.3A neither provisions
private PAGE objects nor migrates their delivery. Their private-storage rollout requires the
separate parent-resource access work; do not migrate such objects on the strength of COVER tests.

## Tests and deployment verification

Unit tests exercise the real SDK presigner offline with fake credentials (exact signed headers,
TTL, key, signature differences), env fail-closed behavior, DTO validation and domain policy.
HTTP integration uses real PostgreSQL and existing session/CSRF/permission services with a fake
ObjectStorage transport. This is NOT proof of bucket ACL, CORS or provider enforcement.

From apps/api, focused tests:

```text
pnpm exec jest --runInBand --runTestsByPath src/storage/storage.spec.ts src/editorial/dto/editorial-upload.dto.spec.ts src/editorial/editorial-uploads.service.spec.ts src/editorial/editorial-manga.mapper.spec.ts
pnpm exec jest --runInBand --runTestsByPath src/storage/storage-objects.spec.ts src/editorial/editorial-cover-validation.spec.ts src/editorial/editorial-finalize.service.spec.ts
node test/run-editorial-isolated.cjs --runTestsByPath test/editorial/editorial-uploads.int-spec.ts
```

The existing isolated runner replays committed migrations in a disposable local `_test` database,
then removes only that database. It never repairs a migration ledger/checksum. This is required
when the configured test DB lacks committed editorial columns.

Before deployment, verify against the selected S3-compatible provider: anonymous access denied;
valid PUT succeeds; wrong key/type/length and expired signatures fail; signed GET succeeds only
after app authorization; CORS permits the approved browser; logs do not capture signed URLs;
bounded GET metadata/body correspondence, conditional final PUT and namespace-scoped DELETE work.
No real S3/MinIO provider validation is claimed by the offline tests.
Timeout regressions observe the real output/timeout chain and inject controlled output
completion errors to test sanitization and slot recovery. They do not claim to wait for or
measure a real ten-second native timeout. APNG and animated WebP fixtures are generated in memory.
